📐 JSON Format — Full Reference
{
  "extractType": "Pre Renewal",      // Name for tab (required)
  "delimiter": "|",                  // |  ,  ~  TAB  (optional)
  "records": {
    "200": {
      "name": "Transaction Record",  // Display name (required)
      "icon": "💳",                  // Emoji (optional)
      "color": "#4ade80",            // Hex color (optional)
      "fields": [
        { "pos": 1, "name": "Record Type",
          "mandatory": true },       // Must not be blank

        { "pos": 2, "name": "Account Number",
          "mandatory": true,
          "format": "^[0-9]{10,12}$" }, // Regex pattern check

        { "pos": 7, "name": "DR/CR Flag",
          "mandatory": true,
          "allowedValues": ["DR","CR"] }, // Exact value check

        { "pos": 8, "name": "Amount",
          "mandatory": true,
          "format": "^[0-9]+(\\.[0-9]{1,2})?$" }, // Numeric format

        { "pos": 9, "name": "Value Date",
          "format": "^[0-9]{8}$" }   // YYYYMMDD date check
      ]
    }
  }
}

⚡ FIS MBP Extract Parser
Version 3 · Browser-based · Zero installation · JSON-driven
🔒 Security: This tool runs entirely in your browser. No data is sent to any server. Safe to use with real extract files.
A standalone tool for testing FIS Modern Banking Platform day-end extract files. Parse any .ext file, view every field by name, and automatically validate mandatory fields, formats, and allowed values — all driven by a simple JSON mapping you define from your FSD.
🚀 Quick Start — 4 Steps
1
Prepare your JSON mapping
Use your FSD to create a JSON mapping file. See the Copilot section below for a shortcut. Or load a template from the ⚙️ Mapping tab.
2
Go to ⚙️ Mapping tab → Paste JSON → Apply
Your mapping is saved in the session. You can save multiple extract types (Pre Renewal, Post Renewal, etc.) and switch between them.
3
Go to 🔍 Parser tab → Paste or Upload .ext file → Parse & Validate
Every record is expanded with field names from your mapping. Validation violations are highlighted in orange immediately.
4
Screenshot for evidence
Expand the record you want to evidence. Press Windows + Shift + S (Windows) or Cmd + Shift + 4 (Mac) to capture. Attach to your test case or defect.
🤖 Generate JSON from FSD using Microsoft Copilot
You don't need to manually write the JSON. Upload your FSD Excel to Copilot and use this prompt:
I have a FIS MBP extract file specification. For each record type in the attached FSD, generate a JSON mapping in exactly this format: { "extractType": "<extract name>", "delimiter": "|", "records": { "<record type code>": { "name": "<record type name>", "fields": [ { "pos": 1, "name": "<field name from FSD>", "mandatory": true/false } ] } } } Rules: - Use the exact field names from the FSD - Set mandatory: true for all fields marked as mandatory in the FSD - Add allowedValues if the FSD lists valid values for a field - Add format regex if the FSD specifies a format (dates, amounts, account numbers) - Output only valid JSON, no explanation
💡 Tip: After Copilot generates the JSON, paste it into the ⚙️ Mapping tab and click Apply. If Copilot wraps it in code fences (```json), remove those before pasting.
✅ Validation Rules Guide
Add rules to your JSON fields to catch issues automatically. After parsing, violations appear in the orange Validation Summary panel and on each affected field card.
RuleExampleCatches
mandatory"mandatory": trueBlank or empty field
allowedValues"allowedValues": ["DR","CR"]Unexpected value e.g. "DB" instead of "DR"
format"format": "^[0-9]{8}$"Wrong format e.g. date as 2026-05-22 instead of 20260522
Common format patterns:
Date YYYYMMDD     →  "format": "^[0-9]{8}$"
Amount            →  "format": "^[0-9]+(\\.[0-9]{1,2})?$"
Account Number    →  "format": "^[0-9]{10,12}$"
Alphanumeric ID   →  "format": "^[A-Z0-9]+$"
Currency Code     →  "format": "^[A-Z]{3}$"
Yes/No Flag       →  "allowedValues": ["Y","N"]
DR/CR Indicator   →  "allowedValues": ["DR","CR"]

❓ FAQ
Can I use this with any extract file, not just FIS MBP?
Yes. As long as you provide the correct JSON mapping, the tool works with any delimited extract file.
What if my extract has thousands of lines?
No limit. The tool processes all lines in one pass. Browser memory handles large files comfortably.
A field has a pipe character inside its value — will it break?
Yes, if the value contains the delimiter unescaped, the field count shifts. This is a data issue in the extract, not a tool issue. The raw line is always shown so you can verify.
The mapping changed — what do I do?
Update your JSON file, paste the updated version in ⚙️ Mapping tab, and click Apply. The old mapping is replaced.
